# 05 复盘

## 最难的问题

1. **确认边界放在哪里**。只靠 prompt 要求“改时间要确认”“不得称已发布”，模型偶尔会违反。最终做法是把边界拆成三层：工具层在写入前拒绝（改时间无待确认项 -> `confirmation_required`，改硬性时间 -> `hard_constraint_violation`），结束时校验结论与账本一致（V1-V8），报告中的事实字段由代码从账本生成。模型仍然自主决定动作，但无法越权写入或虚报结果。
2. **“相同请求只产生一份草稿”与“更换时段后重新提交”同时成立**。若幂等键包含待确认项文字，真实模型两次措辞不同就会产生两份草稿；若只按素材去重，又无法区分换时段的新提交。最终以 `material_id|channel|date|time` 为键：同键原地更新文字，换时段新建并把旧草稿标为 `superseded`，保证任何时刻每个素材只有一份有效草稿。
3. **参考实例的“19:00”不能写死**。替代时间由工具按“小时差升序、同差取晚”计算，并准备第二套排期（17/18/19 均被占）验证会得出 20:00。

## 下一步

- 实现确认回写：用户确认后把草稿从 `pending_confirmation` 改为 `ready`，或拒绝后释放时段。
- 支持跨日期 / 跨渠道的替代方案（需用户先授权放宽硬性要求）。
- 规则从子串匹配升级为可配置的规则引擎或语义审核，并区分渠道规则。
- 草稿存储换成带事务的数据库，支持并发。
- 用更多真实模型对比 live 表现，统计各验收点的通过率。
